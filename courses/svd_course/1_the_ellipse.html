SVD Chapter 1: Circles into Ellipses

The SVD is usually introduced as a factorization to memorize. It is really the answer to one question you can ask about any matrix — which directions does it stretch, and by how much? This chapter asks that question and watches the answer appear as a shape. No factorization until chapter 2.

Forget factorizations. Start with: what does a matrix DO?

A matrix is a machine that eats a vector and returns a vector

Every matrix in this course is one thing: a function. Give it an arrow, it hands you back a different arrow. Our running example, for the whole course:

M = [ 3 0 ] y = M·x [ 4 5 ]

Feed it the two most obvious inputs — the coordinate axes — and read off the answers. (Feeding a matrix e₁ = [1,0] just picks out its first column; that is what matrix–vector multiplication does.)

output — real run M · [1, 0] = [3, 4] length 5.0000 # = column 1 M · [0, 1] = [0, 5] length 5.0000 # = column 2

Both inputs had length 1. Both outputs have length 5. So a reasonable guess: "this matrix stretches things by about 5."

That guess is wrong, and the size of the error is the reason SVD exists.

Try directions the coordinate axes never showed you

Nothing forces us to test only [1,0] and [0,1]. Walk a unit vector around the circle and measure how long the output is at each angle:

output — real run: |M·x| for unit x at angle θ θ= 0° x=[ 1.0000, 0.0000] Mx=[ 3.0000, 4.0000] |Mx| = 5.0000 # e1 θ= 30° x=[ 0.8660, 0.5000] Mx=[ 2.5981, 5.9641] |Mx| = 6.5054 θ= 45° x=[ 0.7071, 0.7071] Mx=[ 2.1213, 6.3640] |Mx| = 6.7082 # biggest θ= 60° x=[ 0.5000, 0.8660] Mx=[ 1.5000, 6.3301] |Mx| = 6.5054 θ= 90° x=[ 0.0000, 1.0000] Mx=[ 0.0000, 5.0000] |Mx| = 5.0000 # e2 θ=120° x=[-0.5000, 0.8660] Mx=[-1.5000, 2.3301] |Mx| = 2.7712 θ=135° x=[-0.7071, 0.7071] Mx=[-2.1213, 0.7071] |Mx| = 2.2361 # smallest θ=150° x=[-0.8660, 0.5000] Mx=[-2.5981, -0.9641] |Mx| = 2.7712

The same matrix stretches one direction by 6.71× and another by 2.24× — a factor of 3 between them — and neither of those directions is a coordinate axis. Both axes happen to land on 5.0, right in the middle, telling you nothing about either extreme.

That is the trap: a matrix's entries are written in coordinates that have nothing to do with what the matrix does. The rows and columns are how it's stored, not how it behaves. To see the behaviour you have to ask in the matrix's own language — and finding that language is exactly what the SVD does.

The question this course answers

Given M, find: which input directions get stretched, and by how much.

Everything else — U, S, V, rank, condition number, low-rank approximation, PCA, LoRA, Muon — is an answer to that one question or a consequence of it. Nothing in this course is a new idea; it is all this sentence, unpacked.

Feed it every direction at once, and a shape appears

The whole set of unit vectors is a circle

The table on page 0 sampled eight angles. Sample all of them — the set of every unit-length input is the unit circle — and push the entire circle through M. Every point on the circle is an input; its image is an output.

A circle goes in; an ellipse comes out. Not sometimes — always, for every matrix. That is the single most useful fact about matrices, and it is enough to define everything that follows.

Why it has to be an ellipse (not an egg, not a blob)

Worth one sentence, because "always" is a strong claim. A matrix is linear: it maps straight lines to straight lines and preserves proportions along them. A circle is the set of points at distance 1; linearity means the image is stretched by a factor that varies smoothly with direction and repeats every half-turn. The only closed curves with that symmetry are ellipses. No matrix can produce a dent, a corner, or an egg — those would need the stretch factor to behave differently at x and −x, and M(−x) = −M(x) forbids it.

An ellipse is described by exactly four numbers — and so is M

Look at what you need to draw that output ellipse and nothing more:

to draw the ellipse you needfor our Mread it as
the direction of its long axisu₁ = [1, 3]/√10which output direction M pushes hardest into
the length of that half-axisσ₁ = 6.7082how hard
the direction of its short axisu₂ = [3, −1]/√10the weakest output direction
the length of that half-axisσ₂ = 2.2361how weakly

A 2×2 matrix has four entries; its ellipse needs four numbers. Nothing was lost — the information was re-expressed, from "how it is stored" into "what it does." That change of description is the entire SVD.

And the two axis directions are perpendicular. That is not a fluke of this example either — an ellipse's axes always are, so the answer always arrives as a clean set of right angles. Check ours:

output — real run u₁ · u₂ = (1×3 + 3×(−1))/10 = 0/10 = 0 # perpendicular

Two families of directions, not one

The axes are outputs. What went IN to produce them?

Page 1 named u₁ and u₂ — the ellipse's axis directions, which live in output space. But every output came from some input. So each axis has a partner: the input direction that lands on it. Page 0's table already found them, we just did not name them:

output — real run the input at 45° — call it v₁ = [1, 1]/√2 — produced the LONGEST output (6.7082) the input at −45° — call it v₂ = [1,−1]/√2 — produced the SHORTEST output (2.2361)

So there are two sets of perpendicular directions in play, and confusing them is the classic beginner mistake:

lives inmeaningours
v₁, v₂input spacethe directions you feed in to hit the extremes[1,1]/√2 and [1,−1]/√2
u₁, u₂output spacewhere those land — the ellipse's axes[1,3]/√10 and [3,−1]/√10
σ₁, σ₂just numbersthe stretch applied on the way6.7082 and 2.2361

They are different vectors. v₁ = [1,1]/√2 is not u₁ = [1,3]/√10, and there is no reason it should be — one is a question, the other an answer.

The one sentence the whole course rests on

M · vᵢ = σᵢ · uᵢ # feed in vᵢ, get out uᵢ stretched by σᵢ

Read it in words: "there is a special set of perpendicular input directions which M maps to a perpendicular set of output directions, doing nothing but scaling on the way." For a general input the matrix rotates and stretches and shears in a tangled way; along the v's it does one clean thing. Check both, with the actual arithmetic:

output — real run M·v₁ = [3,0;4,5]·[0.7071, 0.7071] = [2.1213, 6.3640] σ₁·u₁ = 6.7082 × [0.3162, 0.9487] = [2.1213, 6.3640] same ✓ M·v₂ = [3,0;4,5]·[0.7071,−0.7071] = [2.1213, −0.7071] σ₂·u₂ = 2.2361 × [0.9487, −0.3162] = [2.1213, −0.7071] same ✓

Carry forward

  • A matrix is a function; its entries are storage, not behaviour. Both columns of M have length 5, and neither number is the max stretch (6.71) or the min (2.24).
  • Push the unit circle through any matrix and you get an ellipse — always, because the map is linear.
  • That ellipse needs four numbers: two axis directions and two half-lengths. So does the matrix. Same information, better language.
  • Three named objects: vᵢ input directions, uᵢ output directions, σᵢ stretches — tied together by M vᵢ = σᵢ uᵢ.
  • Nothing has been factored yet. Chapter 2 turns that one equation into the familiar M = U S Vᵀ, and then computes all six numbers from scratch.
