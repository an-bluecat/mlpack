SVD Chapter 2: Where U, S and V Come From

Chapter 1 found the ellipse by sampling angles — a demo, not a method. This chapter turns "the longest axis" into an equation, watches MᵀM fall out of it, and computes the entire SVD of our 2×2 by hand, with numpy only as the referee.

From "M vᵢ = σᵢ uᵢ" to a factorization — by stacking

Two equations, side by side

Chapter 1 ended with one equation per direction. Write both out:

M · v₁ = σ₁ u₁ M · v₂ = σ₂ u₂

Two separate statements. Now the only trick in this chapter: a matrix times a stack of columns is the stack of the individual results. That is simply how matrix multiplication works — column j of M·B is M times column j of B. So glue v₁ and v₂ together as the columns of one matrix V, and the two equations become one:

M · [ v₁ | v₂ ] = [ σ₁u₁ | σ₂u₂ ] ^ call this V ^ this is [u₁ | u₂] with column j scaled by σᵢ

And "scale column j by σᵢ" is exactly what multiplying on the right by a diagonal matrix does. So the right-hand side is U·S with S = diag(σ₁, σ₂):

M · V = U · S

One more step: get V off the left-hand side

We want M alone. Multiply both sides on the right by V⁻¹. Normally that would be work — but V's columns are perpendicular unit vectors, and for such a matrix the inverse is just the transpose:

VᵀV = [ v₁·v₁ v₁·v₂ ] = [ 1 0 ] = I # diagonal 1s: unit length [ v₂·v₁ v₂·v₂ ] [ 0 1 ] # off-diagonal 0s: perpendicular so V⁻¹ = Vᵀ and M·V·Vᵀ = U·S·Vᵀ gives M = U · S · Vᵀ # the singular value decomposition

That is the whole derivation. The famous formula is chapter 1's picture with the two equations stacked into one. Nothing new was assumed — only that the v's are perpendicular unit vectors, which "the ellipse's axes" already guaranteed.

Check VᵀV = I on our actual numbers
output — real run v₁·v₁ = (0.7071)² + (0.7071)² = 0.5 + 0.5 = 1 v₂·v₂ = (0.7071)² + (−0.7071)² = 0.5 + 0.5 = 1 v₁·v₂ = (0.7071)(0.7071) + (0.7071)(−0.7071) = 0.5 − 0.5 = 0

Read it right-to-left: three things happen to your vector

M·x = U·S·Vᵀ·x, and the rightmost factor acts first:

Vᵀ S U x → ROTATE → STRETCH → ROTATE → Mx re-express x scale axis i read the result in v-language by σᵢ out as u-directions

Why does Vᵀ "re-express x"? Because row i of Vᵀ is vᵢ, so entry i of Vᵀx is the dot product vᵢ·x — how much of x points along vᵢ. Then S scales each of those coordinates by its own σ. Then U places the result back into ordinary coordinates.

Every matrix is a rotation, then an axis-aligned stretch, then another rotation. Shear, reflection, projection — all secretly this. The SVD's claim is that no matrix does anything more complicated than that.

Turning "the longest axis" into an equation

State the goal as an optimization

So far we found σ₁ by sampling angles — fine as a demo, useless as a method. Written properly, σ₁ is the answer to:

maximize ‖M x‖ subject to ‖x‖ = 1

Square roots are awkward, and maximizing a positive quantity is the same as maximizing its square, so use ‖Mx‖². Expand it using nothing but the definition ‖y‖² = yᵀy:

‖Mx‖² = (Mx)ᵀ(Mx) = xᵀ MᵀM x

And there it is. The question "which direction does M stretch most?" has, with no cleverness at all, produced the matrix MᵀM. That single line is the door between the geometry and the arithmetic — every derivation of the SVD walks through it.

Why MᵀM is a friendly matrix

Three properties, each with a one-line reason, because the next page uses all three:

propertywhywhat it buys
square (n×n)(n×m)(m×n)eigenvalues are defined at all
symmetric(MᵀM)ᵀ = Mᵀ(Mᵀ)ᵀ = MᵀMits eigenvectors are guaranteed perpendicular — which is what makes the v's an orthonormal set
never negativexᵀMᵀMx = ‖Mx‖² ≥ 0eigenvalues ≥ 0, so √λ is real and σ makes sense

Contrast M itself: not symmetric here, and its eigenvalues (3 and 5) have nothing to do with the stretches 6.71 and 2.24. Squaring it up first is what tames it.

The link: eigenvectors of MᵀM ARE the v's

For a symmetric A, maximizing xᵀAx over unit x is precisely the definition of A's top eigenvector, and the maximum value is its top eigenvalue. With A = MᵀM:

the maximizing x = top eigenvector of MᵀM = v₁ the maximum ‖Mx‖² = top eigenvalue of MᵀM = σ₁² ⇒ σ₁ = √λ₁

You can also verify it straight from Mv = σu, with no eigen-theory at all:

MᵀM v = Mᵀ(Mv) = Mᵀ(σu) = σ·(Mᵀu) = σ·(σv) = σ² v ^ Mᵀu = σv, the same statement read backwards

That last line is the sentence "v is an eigenvector of MᵀM with eigenvalue σ²." Singular values are square roots of eigenvalues — of MᵀM, never of M.

The whole SVD of M, computed with a pen

Step 1 — build MᵀM

M = [ 3 0 ] Mᵀ = [ 3 4 ] [ 4 5 ] [ 0 5 ] MᵀM's entries are dot products of M's COLUMNS: (1,1): col₁·col₁ = 3·3 + 4·4 = 25 (1,2): col₁·col₂ = 3·0 + 4·5 = 20 (2,2): col₂·col₂ = 0·0 + 5·5 = 25 MᵀM = [ 25 20 ] # symmetric, as promised [ 20 25 ]

Step 2 — its eigenvalues

Solve det(MᵀM − λI) = 0:

det [ 25−λ 20 ] = (25−λ)² − 400 = 0 [ 20 25−λ ] (25−λ)² = 400 ⇒ 25−λ = ±20 ⇒ λ = 45 or λ = 5
output — real run: numpy eigenvalues of MᵀM [45. 5.] # matches the hand solve

Square roots, largest first:

σ₁ = √45 = 3√5 = 6.7082 σ₂ = √5 = 2.2361

Exactly the two lengths chapter 1 measured off the ellipse by brute force. Same numbers, now from a formula instead of a sweep.

Step 3 — the eigenvectors give V

For each λ, solve (MᵀM − λI)v = 0 — one line each:

λ = 45: (25−45)a + 20b = 0 → −20a + 20b = 0 → a = b direction [1, 1], normalized: v₁ = [1, 1]/√2 = [0.7071, 0.7071] λ = 5: (25−5)a + 20b = 0 → 20a + 20b = 0 → a = −b direction [1,−1], normalized: v₂ = [1,−1]/√2 = [0.7071, −0.7071]

The 45° and −45° directions from chapter 1's sweep — recovered by algebra rather than by sampling.

Step 4 — U comes free, from M v = σ u

No second eigen-problem needed. Rearranging chapter 1's equation gives uᵢ = M vᵢ / σᵢ:

output — real run M·v₁ = [2.1213, 6.3640], |M·v₁| = 6.7082 = σ₁ # the length comes out right by itself u₁ = [2.1213, 6.3640] / 6.7082 = [0.3162, 0.9487] = [1, 3]/√10 M·v₂ = [2.1213, −0.7071], |M·v₂| = 2.2361 = σ₂ u₂ = [2.1213, −0.7071] / 2.2361 = [0.9487, −0.3162] = [3, −1]/√10 u₁·u₂ = 0.00e+00 # perpendicular, without being asked

Dividing by σ is what makes u a unit vector; the perpendicularity is inherited from the v's — you never impose it.

Step 5 — reassemble and check

output — real run U = [ 0.3162 0.9487 ] S = [ 6.7082 0 ] Vᵀ = [ 0.7071 0.7071 ] [ 0.9487 −0.3162 ] [ 0 2.2361 ] [ 0.7071 −0.7071 ] U · S · Vᵀ = [ 3. 0. ] == M ? True [ 4. 5. ]

Every number on this page was obtainable with a pen; the run is only the referee.

numpy prints some signs flipped — is that a different answer?

No. np.linalg.svd(M) returns U and Vᵀ with both first columns negated relative to ours. That is allowed: flip the sign of both uᵢ and vᵢ and the product σᵢ uᵢ vᵢᵀ is unchanged, so M is reconstructed identically. The SVD is unique only up to these paired sign flips (and up to rotations within any group of equal σ's). The σ's themselves are always unique and always ≥ 0 — those are the numbers you can safely quote. Geometrically: an ellipse's axis is a line, and a line has no preferred arrow direction.

Two free identities to check your work with

output — real run |det M| = 15.0000 σ₁ × σ₂ = 6.7082 × 2.2361 = 15.0000 ✓ ‖M‖²F = 3²+0²+4²+5² = 50 σ₁² + σ₂² = 45 + 5 = 50 ✓

The first says the determinant — the area-scaling factor — is the product of the stretches, which is obvious once you picture a circle of area π becoming an ellipse of area πσ₁σ₂. The second says a matrix's total "size" is split among its singular values — and the whole of chapter 3 is built on that one.
