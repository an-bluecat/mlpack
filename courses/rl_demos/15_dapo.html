GRPO, Debugged Four Times

What DAPO is, and what it is not

DAPO — Decoupled Clip and Dynamic sAmpling Policy Optimization — is chapter 7’s GRPO with four edits. There is no new estimator, no new theory. What makes the paper worth a chapter is that it ablates: it reports what each fix is individually worth on the same benchmark, which is rare and directly useful.

// Headline: Qwen2.5-32B base, AIME 2024 (avg@32)
DeepSeek-R1-Zero-Qwen-32B 47 points
DAPO 50 points, using 50% of the training steps

The objective, diffed against chapter 7's GRPO

Only two things visibly change in the formula; the other two fixes live in how the batch is built and how the reward is computed.

// GRPO (chapter 7): average over responses, then over tokens
L = (1/G) Σi (1/|oi|) Σt min( ri,t·Âi , clip(ri,t, 1−ε, 1+ε)·Âi ) − β·KL
 
// DAPO: one flat average over every token in the batch,
// asymmetric clip bounds, and no KL term at all
L = (1 / Σi|oi|) Σi Σt min( ri,t·Âi , clip(ri,t, 1−ε_low, 1+ε_high)·Âi )
 
// subject to: 0 < |{ correct responses in the group }| < G
// (that constraint IS the dynamic sampling fix)

Note the reward source: a verifier, not a reward model. That single fact is what licenses the most surprising edit in the list — deleting the KL leash — and the last tab explains why.

Fix 1 — Clip-Higher: Stop Strangling Rare Tokens

Step 1 — the disease: entropy collapse

Partway into a GRPO run, the policy’s output distribution sharpens: it becomes very confident about each next token. That sounds like learning, and it kills the run. Chain it out:

// (a) the policy becomes near-deterministic
// (b) so all G = 16 sampled responses come out nearly identical
// (c) so they all get the same reward
// (d) so the group's std = 0 -> every advantage = 0
// (e) so the gradient is zero. Training has stopped.

Steps (c)–(e) are exactly chapter 7’s advantage arithmetic and chapter 10’s dead group. Entropy collapse is a second, sneakier way to manufacture dead groups: not because the problem is too easy or too hard, but because the model stopped being able to disagree with itself.

Step 2 — why the clip is the culprit, on numbers

The clip bounds a ratio, which means the headroom it grants is multiplicative. Take two tokens on opposite ends of the distribution and ask what the standard ε = 0.2 permits in one update:

tokenp_oldceiling = p_old × 1.2absolute headroom
rare / exploratory (e.g. "wait", "recheck")0.010.012+0.002
confident / already-preferred0.901.08 → capped at 1.0+0.10

A rare token may increase its probability by 0.002 per update. For it to become a real option it needs to climb by orders of magnitude, and the clip rations that climb into vanishing slices. Meanwhile the confident token is not constrained by the clip at all — its ceiling of 1.08 is above the maximum a probability can reach anyway.

So the symmetric clip is not symmetric in effect. It barely touches tokens the model already likes and severely rations the ones it might learn to like. That is a ratchet toward determinism.

Step 3 — the fix: decouple the two bounds

// GRPO / PPO: one epsilon for both sides
clip( ratio, 1 − 0.2, 1 + 0.2 )
 
// DAPO: raise ONLY the ceiling
clip( ratio, 1 − ε_low, 1 + ε_high ) // 0.2 and 0.28

What that buys the rare token:

tokenceiling at 1.2ceiling at 1.28headroom change
p_old = 0.010.0120 (+0.0020)0.0128 (+0.0028)+40% more room to grow
p_old = 0.901.08 → capped1.152 → cappedno change — still not the binding limit

The asymmetry is the whole point: raising the ceiling is a targeted gift to low-probability tokens, because they are the only ones the ceiling was actually binding.

Step 4 — why the FLOOR stays at 0.2

Ask the obvious next question: if raising the ceiling helps, why not lower the floor too? Because the two bounds do different jobs. Chapter 5 tab 2 established the clip as a one-sided brake per sample — the ceiling limits how fast something can be promoted, the floor limits how fast something can be suppressed. Loosening the floor would let the model delete tokens from its vocabulary faster, which pushes entropy down. That is the direction of the disease, not the cure.

Fix 2 — Token-Level Loss: One Token, One Vote

Step 1 — spot the nested average in GRPO

L = ( 1/G ) Σi ( 1/|oi| ) Σt loss(token t of response i)
└── outer: average over the G responses
└── inner: average over THAT response's tokens

Every response contributes exactly 1/G of the total loss — a 10-token answer and a 1000-token answer are equal citizens. That sounds fair. Work out what it means per token and it stops sounding fair.

Step 2 — the smallest example: G = 2, lengths 10 and 100

response A (10 tokens)response B (100 tokens)
weight of the whole response1/2 = 0.51/2 = 0.5
weight of ONE token0.5 × 1/10 = 0.050.5 × 1/100 = 0.005
0.05 / 0.005 = 10×
// A token inside the LONG response has one TENTH the influence
// of a token inside the short one. Its length is the only reason.

Step 3 — why that specific bias is dangerous

Now ask where degenerate text lives. Repetition, rambling, abandoned reasoning, gibberish after a wrong turn — these appear in the long responses, essentially by definition. So the nested average under-weights exactly the tokens that most need punishing:

// a 1000-token response that degenerates into repetition gets its
// negative advantage divided across 1000 tokens -> each token barely
// moves -> the repetition pattern is nearly unpunished
 
// Observed consequence: response length and entropy climb unhealthily,
// with no matching accuracy gain.

Step 4 — the fix: one flat average over the batch

L = ( 1 / Σi|oi| ) Σi Σt loss(token t of response i)
 
// Same example: total tokens = 10 + 100 = 110
weight of EVERY token = 1/110 = 0.00909 // identical for both

Follow the consequence for whole responses, because it is the honest trade:

sample-level (GRPO)token-level (DAPO)
response A total weight0.50010/110 = 0.091
response B total weight0.500100/110 = 0.909

So long responses now dominate the loss in proportion to their length. That is intentional: a 100-token response contains 100 decisions, and each deserves the same vote as any other decision. "One response, one vote" was the arbitrary choice; "one token, one vote" is the one that matches where the learning signal actually lives.

Chapter 13 lists the competing cures for the same bias — Dr. GRPO drops the length divisor entirely, Magistral normalizes at group level. TRL now ships a loss_type switch and flags the plain version for exactly this reason.

Fix 3 — Overlong Reward Shaping: Stop Punishing Good Reasoning for Being Cut Off

Step 1 — the false negative

Generation has a hard cap (here 20,480 tokens). A response that hits it gets truncated mid-sentence, so it contains no final answer, so the verifier returns 0. Now look at what the model is told:

response: 20,480 tokens of correct, careful reasoning, cut off
before it could write the final line
verifier: 0 // no answer found
signal: "everything you just did was wrong"
 
// But the reasoning may have been excellent. The 0 is an artifact
// of the length cap, not a judgement about the reasoning.

This is reward noise: a label that is wrong for a reason unrelated to what it claims to measure. And it is not rare — long-CoT training pushes responses toward the cap by design.

Step 2 — remedy A: Overlong Filtering (just delete them)

// If a response was truncated, mask it out of the loss entirely.
// Not "reward 0" — NO gradient contribution at all.
 
// Rationale: a noisy label is worse than no label.

In the ablation this single change is worth +6 AIME points (30 → 36) — the largest jump of any fix except dynamic sampling. Removing wrong labels beat every clever addition.

Step 3 — remedy B: Soft Overlong Punishment (a graduated warning zone)

Filtering alone tells the model nothing about length, so it has no reason to avoid the cap. The second remedy adds a penalty that ramps up as you approach the limit, rather than a cliff at it:

L_max = 20,480 // hard cap
L_cache = 4,096 // width of the warning zone
so the zone starts at 20,480 − 4,096 = 16,384
 
R_length(y) = 0 if |y| ≤ 16,384
( 16,384 − |y| ) / 4,096 if 16,384 < |y| ≤ 20,480
−1 if |y| > 20,480

Check that it is continuous — the three cases meet, they do not jump:

|y|which caseR_length
16,000under the zone0
16,384zone start(16,384−16,384)/4,096 = 0  ✓ matches
18,432mid-zone(16,384−18,432)/4,096 = −0.5
20,480zone end(16,384−20,480)/4,096 = −1.0  ✓ matches the cap case

The penalty is added to the verifier's reward, so a correct-but-very-long answer still nets positive while learning that sprawl is expensive. Compare a cliff: at 20,479 tokens you get full credit and at 20,481 you get −1, which teaches nothing except that the boundary is terrifying.

Fix 4 — Dynamic Sampling: Refuse to Train on Dead Groups

Step 1 — the arithmetic, from chapter 7

GRPO's advantage is a z-score within the group. Run it on a group where all 16 responses got the answer right:

rewards = [1, 1, 1, ..., 1] // G = 16
mean = 1.0
std = 0
Âi = (1 − 1.0) / 0 → 0 // defined as 0 in practice
 
// Same for an all-wrong group: [0,0,...,0] -> std 0 -> Â = 0.
// You generated 16 full responses and learned exactly nothing.

Step 2 — the rule

// Keep a group only if it contains BOTH a right and a wrong answer:
0 < |{ correct responses }| < G
 
// Then oversample: keep generating fresh prompts and discarding
// dead groups until the batch is full of LIVE ones.

Note this is a constraint on the batch, not a term in the loss — which is why it does not appear in the objective on tab 0 except as a side condition.

Step 3 — the price, stated honestly

As the model improves, more groups come back all-correct, so filling a batch costs progressively more generation — reproductions report 3–9× oversampling later in training. DAPO’s bet is that a full batch of live gradients beats a nominal batch that is half zeros, and the ablation backs it: dynamic sampling is the single largest jump in the ladder, +8 points (42 → 50).

You are trading generation compute (cheap, parallel, no gradients) for optimization signal (scarce). That is usually the right trade on modern clusters.

Step 4 — this is one answer to a bigger question

Chapter 10 is the full treatment: keeping GRPO fed with problems that are neither too easy nor too hard is a standing discipline, and dynamic sampling is the online version of it — filter the groups you already generated. The alternatives there filter the prompts ahead of time (difficulty probing, curricula), which is cheaper but goes stale as the model outgrows the filter.

The ablation: what each fix is actually worth

Qwen2.5-32B, AIME 2024 (avg@32), techniques added cumulatively:

configurationAIME 2024gain
Naive GRPO30—

Two things worth noticing, because they generalize past this paper:

  • The two biggest wins (+6 and +8) are both about not training on bad signal — deleting noisy labels, and refusing zero-gradient groups. Neither adds any modelling cleverness.
  • 30 → 50 is a 66% relative improvement on the same model and data, purely from mechanics. Anyone reporting a bare "GRPO gets 30" is reporting an implementation, not a ceiling.

The edit nobody expects: DAPO deletes the KL penalty

Chapter 5 spent a whole tab arguing the KL leash was essential. DAPO removes it. Both are right, and the reason they are both right is the most portable idea in this chapter:

Chapter 5 (RLHF)DAPO
Reward comes froma learned reward modela verifier — is the answer correct?
Can the reward be gamed?Yes — it has blind spots, and the policy hunts them (ch. 5 tab 7, trap 4)No — there is nothing to hack. 23×47 is 1081 or it isn't.
Must the policy stay near π_ref?Yes — that is the only thing keeping it inside the region where the RM is trustworthyNo — and it actively must NOT, since long-form reasoning requires travelling far from a base model
KL leashessentialdeleted

The rule underneath: the KL leash is not a general-purpose safety belt — it is specifically a defence against reward-model error. Replace the learned reward with a checkable one and the thing it was defending against no longer exists. Delete it and you also stop paying the reference model's memory and forward pass.

Chapter 13 records the same move elsewhere: Magistral also drops KL for reasoning RL; ProRL keeps it but periodically resets the reference to the current policy — a ratcheting leash rather than a fixed one.

Review questions

QuestionOne-line answer
"Why does DAPO drop the KL term when PPO needs it?"KL defends against reward-model error; DAPO's reward is a verifier, so there is no proxy to hack — and long-CoT reasoning requires drifting far from the base model anyway.
"Why raise only the upper clip bound?"The clip's headroom is multiplicative, so it binds hard on low-probability (exploratory) tokens and not at all on confident ones; loosening the floor would speed up suppression, which worsens entropy collapse.
"What is entropy collapse and how does it stop training?"The policy goes deterministic, so all G rollouts match, so rewards match, so std = 0 and every advantage is 0 — dead groups by a different route than difficulty.
"Sample-level vs token-level loss — what actually changes?"Per-token weight: nested averaging gives a token in a 100-token response 1/10 the weight of one in a 10-token response, which under-punishes exactly where degenerate text lives.
"Dynamic sampling sounds expensive. Justify it."3–9× more generation, but generation is cheap and parallel while gradient signal is scarce — and it is the biggest single win in the ablation (+8).
"What is the headline result?"50 on AIME 2024 with Qwen2.5-32B vs DeepSeek-R1-Zero-Qwen-32B's 47, at half the training steps — and 30 → 50 from mechanics alone.
