Chapter 4: KL Divergence

The pure waste from using the wrong code — derived step by step

Cross-Entropy = Entropy + Waste

From Chapter 3 we calculated:

Alice using her own code (entropy):    H(p) = 1.75 bits
Alice using Bob's code (cross-entropy): H(p,q) = 2.25 bits
 
// The difference:
waste = 2.25 − 1.75 = 0.5 bits

That 0.5 bits is KL divergence. It's the extra cost you pay — purely because the code doesn't match reality.

Definition

KL(p ‖ q) = H(p, q) − H(p)
 
// Cross-entropy minus entropy
// Total cost minus minimum cost
// = pure waste from mismatch

Deriving the Standard KL Formula — Slowly

Start from what we know

KL(p ‖ q) = H(p, q) − H(p)

Let's expand each side and simplify, one step at a time.

Step 1: Write out both formulas

H(p, q) = Σ p(x) · log(1/q(x))
H(p)    = Σ p(x) · log(1/p(x))

Step 2: Subtract

KL(p ‖ q) = Σ p(x) · log(1/q(x)) − Σ p(x) · log(1/p(x))

Step 3: Factor out p(x) (both sums have same weights)

KL(p ‖ q) = Σ p(x) · [ log(1/q(x)) − log(1/p(x)) ]

Step 4: Use log rule: log(a) − log(b) = log(a/b)

KL(p ‖ q) = Σ p(x) · log( (1/q(x)) / (1/p(x)) )
 
// Simplify the fraction inside the log:
// (1/q) / (1/p) = (1/q) × (p/1) = p/q

Step 5: Final form

KL(p ‖ q) = Σ p(x) · log( p(x) / q(x) )
 
// "For each event: how much more surprised is q compared to p?"
// Weighted by how often the event actually happens (p).

Why the Direction Matters — With Numbers

First, say both directions in BITS — the way chapters 1–3 taught you

Chapter 3 gave the decomposition cross-entropy = entropy + waste, and this chapter called the waste KL. Write that out for each direction and the asymmetry stops being mysterious:

// FORWARD KL — reality is the TEACHER, the code is the STUDENT's
KL(teacher ‖ student) = H(teacher, student) − H(teacher)
      ↑ ↑
bits to send TEACHER's words the unavoidable bits
using the STUDENT's code (teacher's own entropy)
 
// REVERSE KL — reality is the STUDENT, the code is the TEACHER's
KL(student ‖ teacher) = H(student, teacher) − H(student)
      ↑ ↑
bits to send the STUDENT's words the unavoidable bits
using the TEACHER's code (student's own entropy)

The single rule that generates everything else: whoever sits on the left of the ‖ is whose words you are sending — whose distribution you average over. The one on the right only supplies the codebook.

How papers actually write this. The Σ p(x)·log(…) form used on the rest of this tab is the same thing as the E[…] form you will meet in every paper — E is just shorthand for "probability-weighted average":

// what this course writes:

// what a paper writes — identical:

// The subscript x~π_θ IS the weight π_θ(x) moved into the E.
// It is the entire reason this one is REVERSE and not forward.

The convention that creates the asymmetry: what happens at a zero

Both sums use the convention 0 · log(0/x) = 0 — a term with zero weight vanishes, even if its log is infinite. That one rule decides which mistakes are forgiven:

// FORWARD, weighted by teacher:
teacher > 0, student = 0 → log(p/0) = ∞ // CANNOT miss anything
teacher = 0, student > 0 → weight 0, term 0 // may INVENT freely
 
// REVERSE, weighted by student:
student > 0, teacher = 0 → log(q/0) = ∞ // CANNOT invent
student = 0, teacher > 0 → weight 0, term 0 // may MISS freely

So: forward forbids omission and permits invention; reverse forbids invention and permits omission. Everything on the rest of this tab is that table with numbers attached.

First: connect to what you already know

Your understanding is correct: cross-entropy = p(reality) weighted by q(model). Training minimizes it. That's forward KL with one-hot p, which collapses to −log(q(correct class)).

The question is: why does flipping the direction change the behavior so dramatically? The answer is in which distribution provides the weights.

The weight is the key

// Forward KL: Σ p(x) · log(p(x)/q(x)) ← p is the weight
// Reverse KL: Σ q(x) · log(q(x)/p(x)) ← q is the weight
 
// A term only contributes to the sum when its WEIGHT is large.
// Forward KL only "cares about" spots where p is big.
// Reverse KL only "cares about" spots where q is big.

So: what behavior does each direction produce?

DirectionWeightSees through whose eyes?Blows up whenResult
Forward KL(p‖q) p(x) p's eyes — only cares where p is large q is small somewhere p is large q must cover everything p covers. q spreads out.
Reverse KL(q‖p) q(x) q's eyes — only cares where q is large q is large somewhere p is small (or zero) q must stay inside where p exists. q shrinks.

Distillation uses forward KL(teacher‖student): teacher p has weight, so the student cannot ignore anything the teacher finds plausible — "floor" must be covered.

VAE uses reverse KL(encoder‖prior): encoder q has weight, so if the encoder sends images to z=15, it gets crushed — q(z=15) is large and p(z=15)≈0 → blows up.

Distillation: Forward vs Reverse KL Side by Side

First: what forward-KL distillation actually DOES, step by step

You asked whether it is "walk through the teacher’s answer step by step to correct the student’s answer." Almost — with one important correction: there is no student answer. The student never generates anything during forward-KL distillation. The actual loop:

// 1. The TEACHER writes the text. The student does not.
prompt = "Where did the cat sit?"
teacher's text = "The cat sat on the mat ."
 
// 2. Walk the teacher's text position by position. At EACH position,
// ask BOTH models for a full distribution over the vocabulary.
 
position 6, prefix = "The cat sat on the ___"
  teacher says: mat .45 floor .40 roof .08 table .04 dog .03
  student says: mat .97 floor .01 roof .01 table .005 dog .005
 
// 3. The loss AT THIS POSITION is the forward KL between those two
// distributions — the 1.43 bits computed further down this tab.
loss_6 = KL(teacher ‖ student) = 1.43 bits
 
// 4. Average over every position of the teacher's text, then backprop.
// The student is only ever SCORING, never writing.
loss = mean( loss_1, loss_2, ..., loss_T )

So the correction to your mental model: it is not two answers being compared. It is one text — the teacher’s — with the student asked at every position "what would you have predicted here?"

And this reveals what "distillation" adds over ordinary fine-tuning. Suppose you kept only the token the teacher actually wrote, as a hard target:

// SFT: target is one-hot at "mat" — p = (1, 0, 0, 0, 0)
KL(one-hot ‖ student) = 1 × log(1 / 0.97) = 0.044 bits
= −log(student(mat)) // ...which is just cross-entropy!
 
// (a one-hot p has H(p) = 0, so KL = H(p,q) − 0 = H(p,q) exactly)
 
// Distillation: target is the teacher's SOFT distribution
KL(soft teacher ‖ student) = 1.43 bits

Same direction, same formula — but the one-hot version says only "mat was right," while the soft version also says "and floor was almost as good, and dog was nearly impossible." That extra structure is the whole point of distillation, and it means ordinary SFT is just forward-KL distillation from an infinitely confident teacher.

Read the two rows. They reach exactly opposite verdicts, and each calls the other’s favourite infinitely bad. Not a difference of degree — they are answering different questions:

  • Forward is horrified that B omits "taxi", which the teacher genuinely says. It does not care at all that A puts ⅓ on nonsense — the teacher’s weight there is 0, so that term vanishes.
  • Reverse is horrified that A invents the nonsense blend. It does not care at all that B ignores "taxi" — the student’s weight there is 0, so that term vanishes.

Then notice which student you would rather ship. A, the forward-KL winner, will actually emit "take the train taxi" a third of the time. B just tells you to take the train.

So reverse KL is what ON-POLICY distillation is — with the actual formula

Two separate choices get conflated here, so pull them apart:

whose text do you train on?which direction at each position?
classic distillationthe teacher’s (off-policy)forward
on-policy distillationthe student’s own samplesreverse

They pair naturally rather than by coincidence: if you sample from the student, then the average you compute is automatically an average under the student — and "expectation under the student" is the definition of reverse KL. Sampling on-policy hands you the reverse direction for free.

// Thinking Machines' on-policy distillation, per token:
 
// 1. the STUDENT generates the text (so we sit on its own states)
// 2. the teacher scores each token the student actually chose
// 3. per-token advantage:
 
advantage_t = −( log π_student(token_t) − log π_teacher(token_t) )
 
// Read it in bits: "how many EXTRA bits does the teacher spend
// encoding the token I just chose?" — exactly the reverse-KL term
// from the top of tab 3, estimated at the sampled token.
//
// Maximizing this advantage = minimizing reverse KL.

Two properties the post highlights, both readable straight off the asymmetry table:

  • Mode-seeking. Reverse KL forbids invention and permits omission → the student commits to one teacher-approved behaviour instead of spreading across several suboptimal ones.
  • "Unhackable." Low reverse KL guarantees that the text you actually produce is text the teacher finds likely — because reverse KL only ever measures text you produce. Low forward KL carries no such guarantee: student A above has excellent forward KL and still emits nonsense a third of the time.

It also cures compounding error: the student is graded on the states it actually reaches — including ones it reached by mistake — so the teacher supplies recovery behaviour exactly where the student needs it. Reported on Qwen3: 17,920 GPU-hours (RL, 67.6% AIME’24) → 1,800 GPU-hours (on-policy distillation, 74.4%).

Easy thing to get wrong: you do not generate with both models. In each setup exactly one model writes the text and the other only scores it — and which is which swaps between the directions.

Traced over a whole answer, not one token:

// ---- FORWARD: the teacher writes ----

advantage_t = −( log π_student − log π_teacher )
// the teacher generated NOTHING — it only graded.

Now look at where the student wrote 900. The teacher scores that position and says "given the prefix 23×40=, I'd give 9 almost no probability" — a large penalty landing exactly on the error. And at the next position, with prefix ...=900,, the teacher still supplies a distribution — telling the student how to continue from inside its own mistake. Forward KL can never do this, because the string 900 appears nowhere in the teacher's text.

The practical consequence, which is the one that decides your infrastructure:

forward → the teacher's text is generated ONCE, cached, reused forever
→ no teacher needed at training time at all
 
reverse → the student's text changes every single step
→ the teacher must be LIVE in memory, scoring, every step
Pedantic but important: "forward ⇒ teacher generates" is a convention, not a law

These are two independent choices:

axis 1: whose text do you train on? teacher (off-policy) | student (on-policy)
axis 2: which direction per position? forward | reverse

They get welded together only when you score the sampled token alone (one number per position). Then whoever sampled decides the direction, because the average is automatically taken under the sampler. That is the cheap estimator on-policy distillation uses.

If instead you compute the full vocab sum at each position, you may choose freely. Student-generated text with forward KL at each position is a real published method (GKD). So the pairing follows from the estimator, not from the definition.

Then why does the literature default to FORWARD KL at all?

Fair question, given everything above. Five reasons, and the first is decisive:

1. Forward KL is supervised learning. Reverse KL is reinforcement learning. That is not a slogan — it falls out of where θ sits:

// FORWARD: θ appears only INSIDE the bracket.
KL = Ex∼π_teacher[ log π_teacher − log π_θ ]
↑ does NOT depend on θ
→ just backprop through log π_θ. A drop-in swap for your SFT loss.
 
// REVERSE: θ is ALSO in the thing you sample from.
KL = Ex∼π_θ[ log π_θ − log π_teacher ]
↑ DEPENDS on θ
→ you cannot just differentiate the inside. You need the score-function
(REINFORCE) trick to differentiate through the sampling itself.

So reverse KL drags in the entire policy-gradient apparatus: a generation loop inside the training loop, an inference engine, weight syncing. Forward KL is a loss function; reverse KL is a training system. For most of distillation’s history nobody wanted to pay that.

One honest qualification, since "needs RL" can sound worse than it is. On-policy distillation routes the reverse KL through an RL loss, but with a discount factor of zero — each token optimizes only itself. So it needs the RL plumbing (sampling loop, importance-sampling loss) but none of RL's hard part: no value model, no GAE, no credit assignment over time, because each token's reward is already attached to that token. See RL ch. 11 tab 5 for the loop.

2. Distillation was invented for classifiers, where the problem does not exist. Hinton's 2015 setting has a fixed set of inputs and no generation — so no autoregressive prefixes, no compounding error, no exposure bias. Forward KL is simply the right answer there. Every reverse-KL argument on this tab is specific to sequence generation, which only became the dominant use case recently.

3. Mode-seeking is a genuine cost, not only a benefit. If the teacher has five valid ways to answer, reverse KL teaches one. You lose diversity — bad for creative tasks, for sampling variety, and for general-purpose students.

4. Reverse KL can drop capabilities silently. Recall "permits omission": if the student never explores some region, the loss never notices it is missing. A whole skill can vanish and the training curve stays clean. Forward KL cannot hide that — anything the teacher does and the student does not is an infinite penalty.

5. It needs a student that is already decent. Reverse KL commits to whichever mode the student currently has. Run it on a weak student and it confidently locks in something mediocre. So the usual pipeline is: get into a sensible region first with SFT or forward KL, then sharpen with reverse KL on-policy.

Your objection, answered: "but the teacher IS the real distribution — shouldn’t we use it?"

Right thing to be bothered by. The resolution: the left slot of KL(· ‖ ·) does not mean "who is correct." It means whose text we are measuring.

question you might want answeredthe KL that answers it
"How well does the student describe the teacher?"forward — averaged over teacher text
"How much would the teacher object to what the student says?"reverse — averaged over student text

At deployment, the student writes the text. So the quantity that predicts how good your shipped model is, is the second one. Forward KL spends most of its attention on text the student will never produce.

There is also a capacity argument underneath, which is why this is not merely philosophical. A smaller student genuinely cannot match the teacher’s full distribution. Forced to approximate, the two directions fail in opposite ways:

forward → hedge across every teacher mode
→ mass lands BETWEEN modes, where the teacher has none
→ student emits blends the teacher would never write
 
reverse → commit to one mode the teacher likes
→ less diverse, but everything it says is teacher-approved

So "the teacher is correct" argues for reverse KL, not against it: trusting the teacher means wanting everything you say to be something the teacher would say — and that is reverse KL’s question, not forward’s.

State of the art: is reverse KL used for LLM distillation?

Yes — recent papers argue forward KL alone isn't enough for LLMs.

MethodKL directionMotivation
Classic distillation
(Hinton 2015)		Forward KL(teacher‖student)Student covers all teacher knowledge. Standard for classification.
SeqKD
(Kim & Rush 2016)		Forward KL via sequence-level samplingEarly LLM distillation. Student learns teacher's likely outputs.
DistiLLM
(Ko et al. 2024)		Reverse KL(student‖teacher)Forward KL causes student to spread over all plausible teacher outputs — too diffuse. Reverse KL makes student commit to one good mode.
MiniLLM
(Gu et al. 2024)		Reverse KL(student‖teacher)Showed that forward KL causes exposure bias in autoregressive generation. Reverse KL generates more fluent, committed responses.

(2024–25)		α·forward + (1−α)·reverseBest of both: don't omit teacher knowledge AND don't hallucinate.

The intuition for MiniLLM/DistiLLM: in autoregressive generation the student generates token by token from its own outputs. Forward KL spreads the student over all teacher modes — but the student can only ever follow one path, so the spread becomes incoherent. Reverse KL forces the student to commit: "pick one good mode and stay there."
