3. Why ELU+1 and a denominator?

Separate positive features, normalized weights, and LayerNorm. They solve different problems.

Derive ELU+1

Start from the function you asked about

ELU(x) = x if x > 0 exp(x) − 1 if x ≤ 0 (alpha = 1) φ(x) = ELU(x)+1 = x+1 if x > 0 exp(x) if x ≤ 0

Negative coordinates become small positive features; positive coordinates keep a linear slope. Apply this independently to every coordinate of Q and K. The feature map itself has no trainable parameters here.

x = torch.tensor([-2., -1., 0., 1., 2.], dtype=torch.float64)
features = F.elu(x) + 1

Output — real CPU run, float64, PyTorch 2.8.0

x        = [-2, -1, 0, 1, 2]
features ≈ [0.135335, 0.367879, 1, 2, 3]
Refresher: why not plain Q @ K.T?

You can reassociate a signed dot product too. But negative similarities need not define a weighted average, and their row sums can cancel to zero. Positive features make the normalized mixture easier to interpret and the denominator positive in exact arithmetic.

Normalize across keys

The denominator controls accumulated mass

one value = [2,0], weight = 3 weighted sum = [6,0] weighted average = [6,0]/3 = [2,0] repeat that key/value 10 times: weighted sum = [60,0] weighted average = [60,0]/30 = [2,0]

More stored tokens should not automatically multiply the output magnitude. The denominator divides out total match strength. This is row normalization across keys; it is not normalization across a token’s feature coordinates.

OperationWhat it normalizesRole
ELU+1Nothing: coordinatewise mappingConstruct positive features for similarity
Divide by Σ weightsEach query’s weights across keysProduce a weighted average
LayerNormOne token’s hidden feature vectorControl hidden activation scale
Refresher: can I keep softmax over Q and K separately?

Separate feature normalizations can define other efficient attention rules. They do not generally equal row-softmax of QKᵀ. Always write the exact resulting weights before claiming equivalence.

Epsilon and magnitude

This epsilon belongs to a different operation

den = (Qf * key_sum.unsqueeze(-2)).sum(-1, keepdim=True) y = numerator / den.clamp_min(1e-6)

Here the denominator is a sum of similarities, not a variance. There is no square root. The clamp is a lower bound to avoid dividing by zero if finite-precision features underflow to zero. Above the floor it changes nothing; below the floor the weights need not sum to one.

Does it lose magnitude information?

At the mapped-feature level, multiplying one query u by any positive scalar scales both numerator and denominator equally, so its output is unchanged while the floor is inactive. Scaling every key feature by one common positive scalar also cancels. Scaling only one key generally changes its relative importance.

But φ(cq) generally differs from cφ(q). The ELU+1 map has an offset and a nonlinear negative branch. Scaling a raw query before the map need not cancel.

Refresher: is this the same as softmax temperature?

No. Increasing the magnitude of a raw softmax query usually sharpens its score distribution. Scaling a mapped query in normalized kernel attention cancels instead. That difference affects expressiveness, not just arithmetic cost.

Derivatives and questions

The feature map supports backward

φ′(x) = 1 if x > 0 exp(x) if x ≤ 0

Both sides have derivative 1 at zero, so the map is smooth there to first order. The negative tail can still have tiny derivatives. Positive features do not guarantee perfect gradient flow.

Numerical limits are real

In floating point, F.elu(x)+1 can round to zero for very negative x. Accumulating a long state in a low precision dtype can also lose accuracy. The lab uses float64 for verification. Practical kernels often use higher precision for state accumulation and carefully chosen stabilization; a denominator floor is not a cure for arbitrary overflow.

Check yourself

What if V has negative coordinates even though the weights are positive?

Show the reasoning

That is fine. Positive weights describe how values are mixed; they do not require positive payloads. With an inactive floor the output remains a convex combination of value vectors and can contain negative coordinates.

Check yourself

Can you insert /sqrt(Dk) after the feature dot product?

Show the reasoning

Any positive global scaling of all weights cancels between numerator and denominator, provided the floor is inactive. Scaling the raw inputs before φ is a different operation and can change the answer.
