2. Change the rule, then move the parentheses

One three-token example proves what is preserved and what is changed.

Softmax blocks the shortcut

The tempting move that fails

softmax(Q @ K.T / sqrt(Dk)) @ V ≠ Q @ (K.T @ V)

Associativity rearranges matrix multiplication. It cannot move a nonlinear softmax through a product. We first choose a new similarity that factors into mapped query/key vectors.

A normalized positive dot product

u_i = φ(q_i) a_j = φ(k_j) w_ij = u_i · a_j y_i = Σ_j (w_ij v_j) / Σ_j w_ij

The numerator accumulates payloads; the denominator turns their nonnegative weights into an average. A “kernel” here means the similarity function κ(q,k)=φ(q)·φ(k). It is unrelated to a GPU program also called a kernel.

Refresher: is ELU+1 secretly an approximation of softmax?

It defines a different kernel. Performer designs random features to approximate the exponential similarity used by softmax; ELU+1 by itself has no such equality or approximation guarantee.

All pairs with numbers

Define every input

raw Q = raw K = [[0,0], [0,1], [1,0]] φ(Q) = φ(K) = [[1,1], [1,2], [2,1]] V = [[2,0], [0,4], [6,2]]

There are three tokens and two features. Q and K are equal only to simplify this example. We will derive ELU+1 in lesson 3; for now use the mapped vectors shown.

Trace the second output

q₂ features = [1,2] weights = [1,2] · each key = [3,5,4] numerator = 3[2,0] + 5[0,4] + 4[6,2] = [30,28] denominator = 3+5+4 = 12 y₂ = [30,28]/12 = [2.5, 2.333333…]

Each token here can read all three values. This is bidirectional attention; it is not yet a causal language-model layer.

The small summary

Build S and z once

S = φ(K).T @ V shape (M,Dv) z = Σ_j φ(k_j) shape (M,) numerator = φ(Q) @ S denominator = φ(Q) @ z output = numerator / denominator[:,None]

Expand one entry: S[0,0] = 1×2 + 1×0 + 2×6 = 14. The time axis has been summed out. Every query can now read this table instead of visiting every token.

Refresher: why is that denominator the same?
Σ_j (u_i · a_j) = u_i · (Σ_j a_j) = u_i · z

The query is fixed while summing over keys. Distributivity lets it leave the sum. The numerator uses the same move, with each key multiplied by its value.
