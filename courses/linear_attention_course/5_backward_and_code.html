Gradients through the read

The quotient has two gradient paths

u: mapped query (M,) S: memory (M,Dv) z: key sum (M,) y: output (Dv,) d = uᵀz y = Sᵀu / d g = ∂L/∂y assume d is above the floor ∂L/∂S = u gᵀ / d ∂L/∂z = −u (g·y) / d ∂L/∂u = (Sg − z(g·y)) / d

S and z both depend on keys. A key affects the numerator and the denominator, so treating the denominator as a constant produces the wrong gradient. These are derivatives of the ordinary quotient rule, not a special training trick.

Refresher: how do I get the first derivative without matrix calculus?

Output coordinate b is y_b = Σ_a u_a S_ab / d. Change only S_ab while holding u,z fixed: y_b changes by u_a/d. Multiply that by the upstream derivative g_b. Therefore the whole S derivative has entries u_a g_b/d.

Backprop through a write

S_t = S_(t−1) + a_t v_tᵀ ∂S_t / ∂S_(t−1) = identity if G = ∂L/∂S_t, then write contributes: ∂L/∂v_t = Gᵀ a_t ∂L/∂a_t = G v_t (plus the z-path derivative)

The additive state offers a direct path into earlier writes. Future losses add to each token’s gradients. Raw Q/K gradients then multiply by the feature-map derivative; projection weights train by the usual chain rule. This does not guarantee all gradients stay well scaled.

Read the zero rows correctly

The first two query rows have zero gradients because this loss uses only the last output; earlier queries do not write to S. Earlier keys and values do receive gradients because the last query reads their writes. In a larger model with losses at every position, other paths will contribute too.

def linear_attention(q, k, v, eps=1e-6):
    """Bidirectional: all query positions can read all key/value positions."""
    qf, kf = phi(q), phi(k)
    state = kf.transpose(-1, -2) @ v        # (B, H, M, Dv)
    key_sum = kf.sum(dim=-2)               # (B, H, M)
    numerator = qf @ state                # (B, H, T, Dv)
    denominator = (qf * key_sum.unsqueeze(-2)).sum(-1, keepdim=True)
    return numerator / denominator.clamp_min(eps)
Refresher: why unsqueeze(-2), not unsqueeze(-1)?

key_sum is (B,H,M). We want to reuse it for every time position, so insert time before M: (B,H,1,M). It then multiplies qf of shape (B,H,T,M). Sum the last feature axis with keepdim=True to get (B,H,T,1).

def recurrent_attention(q, k, v, initial_state=None, eps=1e-6):
    """Inclusive causal attention; returns output and state for continuation.

    Uses out-of-place additions so autograd can retain the earlier states.
    For inference, call inside torch.no_grad(). For full BPTT, do not detach
    the returned state between chunks. At least one token is required.
    """
    qf, kf = phi(q), phi(k)
    if initial_state is None:
        state = q.new_zeros(*q.shape[:2], qf.shape[-1], v.shape[-1])
        key_sum = q.new_zeros(*q.shape[:2], qf.shape[-1])
    else:
        state, key_sum = initial_state
    outputs = []
    for t in range(q.shape[-2]):
        qt, kt, vt = qf[:, :, t], kf[:, :, t], v[:, :, t]
        state = state + kt.unsqueeze(-1) * vt.unsqueeze(-2)
        key_sum = key_sum + kt
        numerator = (qt.unsqueeze(-2) @ state).squeeze(-2)
        denominator = (qt * key_sum).sum(-1, keepdim=True)
        outputs.append(numerator / denominator.clamp_min(eps))
    return torch.stack(outputs, dim=-2), (state, key_sum)

This function is bidirectional

It is the rule in your TorchCode linear-attention exercise. A GPT needs the causal recurrence or a verified causal chunk/scan implementation. Reusing the full KᵀV in a causal language model leaks future tokens.
