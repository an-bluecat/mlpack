1. Where the quadratic cost comes from

Start with the dimensions in your notes. Separate a full sequence from one cached decode step.

Your matrix shapes

Fix the axes before counting work

Use one head first. T is the number of tokens, Dk the query/key width, Dv the value width. A matrix product (a,b) @ (b,c) makes a×c outputs; each needs b multiply-adds. Its work is proportional to a×b×c.

TensorShapeWhat one row means
QT × DkA token asking for information
KT × DkA token offering a match
VT × DvA token’s payload
QKᵀT × TOne query’s scores against every key
outputT × DvA weighted mixture of values

Your quadratic count is right

Q @ K.T: (T,Dk) @ (Dk,T) → (T,T) work T²Dk weights @ V: (T,T) @ (T,Dv) → (T,Dv) work T²Dv

If Dk=Dv=D, the attention mixing work is O(T²D). Softmax also touches T² entries. This excludes Q/K/V and output projections, which add their own work.

Refresher: does “linear attention” mean an nn.Linear layer?

No. Here “linear” means the mixing work grows in proportion to T when the feature widths stay fixed. Q/K/V projections can still be nn.Linear layers, and the full attention module can still be nonlinear.

Count the work

Why change the multiplication order?

Your notes correctly use (QKᵀ)V = Q(KᵀV) when no softmax is between them. KᵀV is Dk×Dv, so the main products cost O(T Dk Dv) rather than O(T²(Dk+Dv)). The next lesson shows why a feature map and a denominator are needed for a useful replacement.

Counts are scalar multiply-accumulates for the two numerator matrix products only. They exclude projections, mapping, normalization, masking, memory movement and backward. They are calculated counts, not timings or speedup measurements.

General feature maps have their own width

Call the mapped width M: φ(Q) is T×M. The numerator costs O(T M Dv); the denominator adds O(T M). Mapping Q and K also costs something. For ELU+1, M=Dk; for a random-feature map, M can be different.

The KV cache saves projections, not the query’s search

During decoding, only the new token’s Q/K/V projections are computed. Its query still compares with all cached keys and mixes the cached values. That one step is linear in the current prefix length. Recurrent linear attention instead updates and reads the fixed-size state.

Refresher: is training sequential because the state is recurrent?

A simple Python reference loops over tokens. Training implementations can use prefix scans or chunks, exposing parallel work while keeping total work linear for fixed widths and chunk size. Recurrent generation is sequential in either model because the next token depends on the token just generated.

FlashAttention and checkpoints

FlashAttention keeps the softmax rule

It tiles exact softmax attention to reduce memory traffic and avoid storing the entire T×T score matrix in device memory. Its dense attention arithmetic still grows quadratically with sequence length. Linear attention changes the similarity rule or approximates it so a compact state is possible. See Dao et al. (2022), FlashAttention.

Check yourself

If you double T at fixed widths, what happens to the mixing work? What about one cached decode step?

Show the reasoning

Full dense softmax mixing grows about 4×; linear mixing grows about 2×. A single cached softmax step at a doubled prefix is about 2×; a fixed-width recurrent step is approximately unchanged. These are operation-count statements, not latency guarantees.
