4. A causal attention layer is a recurrent memory

Use only the prefix. Write the current token, read the current state, then continue.

One outer-product write

A dot product scores; an outer product stores

mapped key a₁ = [1,1] value v₁ = [2,0] a₁[:,None] * v₁[None,:] = [[1],[1]] * [[2,0]] = [[2,0], [2,0]]

Each row is a key-feature channel; each column is a value coordinate. Multiplying a later query by this table retrieves a similarity-weighted value. The same write operation handles a much larger feature space.

Two pieces of state, initialized to zero

S₀ = zeros(M,Dv) z₀ = zeros(M) S_t = S_(t−1) + a_t v_tᵀ z_t = z_(t−1) + a_t y_t = (u_tᵀ S_t) / (u_tᵀ z_t)

The state is calculated from the input history; it is not a weight matrix learned by optimizer.step(). The projections generating queries, keys and values are learned.

Refresher: why write before read?

Standard causal self-attention includes the current token: j≤t. Write then read reproduces that. Read then write instead uses j<t, a different valid convention that needs separate treatment for the first token.

Chunks and parallel training

Split a chunk’s answer into past and local contributions

U = mapped queries in this chunk A = mapped keys in this chunk W_local = tril(U @ A.T) num = U @ S_in + W_local @ V_chunk den = U @ z_in + W_local @ ones S_out = S_in + A.T @ V_chunk z_out = z_in + sum(A, time)

S_in and z_in describe everything before the chunk. The triangular local matrix includes only current/past tokens inside the chunk. Updating the incoming state with the whole chunk before computing its outputs would leak future tokens.

Why use chunks?

A chunk turns many tiny state operations into larger matrix multiplications that hardware can handle efficiently. For fixed chunk size C, local pair work costs O(T C M) and value mixing O(T C Dv), plus state work O(T M Dv). A sequential chunk loop is an educational implementation; optimized training also coordinates chunks and backward carefully.

Refresher: is a cumsum of outer products constant memory?

No. Forming every token’s outer product and every prefix state as a tensor of shape T×M×Dv uses O(T M Dv) storage. It can be a useful small reference, but it is not the fixed-state streaming implementation.

Cache bytes and boundaries

One head, T=4096, Dk=M=Dv=64, float32Bytes / size
Stored dense T×T weights alone4096²×4 = 67,108,864 bytes = 64 MiB
Softmax KV cache4096×(64+64)×4 = 2,097,152 bytes = 2 MiB
Linear S and z(64×64+64)×4 = 16,640 bytes = 16.25 KiB

These are calculated tensor sizes per sequence, per head, per layer. Multiply by batch size, heads and layers as appropriate. They exclude weights, outputs, allocator overhead and training activations. FlashAttention does not require storing that full dense weight table.

Inference memory versus training memory

Streaming inference can retain only S and z (plus whatever else the model needs). Standard autograd training retains history needed for backward, so this Python recurrence uses memory that grows with T. Efficient backward algorithms and recomputation can reduce intermediate storage; total training memory is not O(1).

Continue one sequence; reset between unrelated sequences

Pass the final state into the next chunk of the same example. In inference, use no_grad(). In full-sequence training, keep the graph connected. Detaching state intentionally truncates gradients. Reset state for a new document or request unless the task explicitly calls for carrying its history.
