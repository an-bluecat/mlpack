How to make latents mean what you want — supervised routing

Autoencoder vs MLP vs VAE — What's the Actual Difference?

Autoencoder — compression + reconstruction of the SAME thing

An autoencoder compresses input into a small bottleneck, then reconstructs the exact same input as output. The only goal is: output ≈ input.

// Image autoencoder (Chapter 1 of this course):
input: [1, 1, 1, 1] // "bright" 2x2 image
encoder: [1,1,1,1] → z = 0.8 // squeeze to 1 number
decoder: 0.8 → [0.97, 0.98, 0.96, 0.97] // reconstruct the SAME image
loss = MSE(input, output) // how well did we reconstruct?
 
// The "auto" means self. It encodes itself, then decodes itself.
// Not predicting a label. Not classifying. Just: compress and recover.

Is autoencoder just an MLP? Almost — the bottleneck is the difference

// Plain MLP (e.g. image classifier):
[1,1,1,1] → [hidden: 32 nodes] → [output: "cat" or "dog"]
// No bottleneck. 32 nodes can use all information freely.
 
// Autoencoder:
[1,1,1,1] → [encoder: 16 nodes] → [bottleneck: 1 node] → [decoder: 16 nodes] → [1,1,1,1]
// Same math as MLP (weights, activations, backprop).
// BUT: the bottleneck forces compression.
// All information about the input must pass through 1 number.
// The network learns what's important enough to keep.
 
// So: autoencoder = MLP with a narrow middle + reconstruction loss.
// The bottleneck + reconstruction objective is what makes it special.

What VAE adds on top of autoencoder

Autoencoder bottleneck: a single crisp number per input.

VAE bottleneck: a distribution (mean + std) per input. Then sample from it.

// Autoencoder: encoder → z = 0.8 (always exactly 0.8 for "bright")
// VAE: encoder → μ=0.8, σ=0.2 → sample z ~ N(0.8, 0.04)
// maybe z=0.75 this time, z=0.91 next time
 
// Why does this matter?
//
// Autoencoder latent space: "bright" → exactly 0.8 (point)
// Nothing at z=0.79 or z=0.81 was ever trained.
// Sample a random z → likely garbage.
 
// VAE latent space: "bright" → cloud around 0.8 (distribution)
// Decoder sees z=0.75, 0.81, 0.91, 0.73... all during training.
// Learns what to do everywhere in that region.
// Sample a random z → smooth, valid output.
 
// The VAE cloud also forces neighboring inputs to overlap:
// "bright" cloud at z≈0.8 bleeds into "half" cloud at z≈0.0
// → decoder learns the whole space between them
// → smooth interpolation, no gaps

You're right — the YouTube system's decoder predicts labels (watch time, likes), not a reconstruction of the input. Standard VAE does reconstruct the input. This system borrows VAE's tools (μ/σ, reparameterization, KL) but uses them for supervised prediction. The correct name is variational information bottleneck. The "VAE" label they use is loose.

Wait — Aren't the 3 Numbers Random?

The right question to ask

In a standard VAE (Chapter 2), the latents organize themselves however the network finds useful. You get z1, z2, z3 — but you have no idea what they mean. z1 might encode "brightness" or "aspect ratio" or something uninterpretable.

YouTube's system claims z_passive = "how much was consumed", z_active = "how actively engaged", z_valence = "positive or negative." But how? If it's a VAE, aren't those 3 numbers just random?

The answer: routing forces semantics

In a standard VAE, all latents see all outputs:

// Standard VAE: all latents → one decoder → all outputs
[z1, z2, z3] → decoder → [watch_time, likes, dislikes, shares]
// z1, z2, z3 can mean ANYTHING. No constraint on semantics.

In this system, each latent is routed to only one specific decoder predicting only one specific label:

z_passive → watch_time decoder only → predicts: how much did they watch?
z_active → response decoder only → predicts: did they engage at all?
z_valence → sentiment decoder only → predicts: was engagement positive?
 
// Each latent has no choice — it must encode what its decoder needs.

Why the Architecture Forces Each Latent to Mean What It Should

Think through z_passive step by step

// z_passive is the ONLY input to the watch-time decoder.
// The decoder sees nothing else — no video features, no user history.
 
// Training example: user watched 90% of a video.
// Encoder outputs: z_passive = 0.2 (low)
watch_time_decoder(z_passive=0.2) → predicts: 15% watch ratio
ground_truth: 90% watch ratio
loss = (15% - 90%)² = large!
 
// Backprop: gradient flows from loss → decoder → z_passive
// "z_passive needs to be HIGHER to predict 90% watch ratio"
// → encoder is forced to output a higher z_passive for this user
 
// Repeat for 100M training examples.
// z_passive converges to: "high when user watched a lot, low when they didn't"
// Not because we told it to. Because that's the ONLY way to minimize loss.

Same logic for z_valence

// z_valence is the ONLY input to the sentiment decoder.
// Training example: user clicked Like.
// Encoder outputs: z_valence = -1.5 (negative)
sentiment_decoder(z_valence=-1.5) → predicts: P(liked|responded) = 0.18
ground_truth: user liked = 1.0
loss = large
 
// Backprop: "z_valence needs to be POSITIVE to predict a like"
// → encoder forced to output positive z_valence when user liked
// → encoder forced to output negative z_valence when user disliked
 
// After training: z_valence > 0 means "positive sentiment", < 0 means "negative"
// Emerged from data. Not hand-coded. But not random either.

The contrast with standard VAE

Standard VAE

All latents → one big decoder → all outputs.

z1 might encode "redness of thumbnail" — it doesn't matter, as long as the decoder can reconstruct the image from all 3 combined.

YouTube Supervised VAE

Each latent → its own decoder → its own specific label.

z_passive MUST encode watch behavior because it's the ONLY thing its decoder can see.

The Full Architecture — Every Connection Shown

Encoder: features → 3 latent distributions

// Input: user features + video features + context
encoder(features) → [μ_passive, σ_passive, μ_active, σ_active, μ_valence, σ_valence]
// 6 numbers: mean + std for each of the 3 latents
 
// Reparameterization (same as Chapter 2):
z_passive = μ_passive + σ_passive × ε₁ // ε₁ ~ N(0,1)
z_active = μ_active + σ_active × ε₂
z_valence = μ_valence + σ_valence × ε₃

What the "VAE" part actually adds (vs plain supervised learning)

// Could we just have: encoder → 3 numbers → 3 decoders (no sampling)?
// Yes. That would be a regular autoencoder with supervised routing.
 
// The VAE part (μ, σ, reparameterization) adds:
// 1. Smooth latent space — similar users get similar z values
// 2. KL regularization — keeps latents well-behaved, prevents collapse
// 3. Uncertainty — σ captures "how confident are we about this user's state?"
// High σ_passive = "we've seen this user very little, uncertain about their consumption"
// Low σ_passive = "we know this user well, confident prediction"

The Debiasing Trick — Separating Signal from Noise

The problem: raw watch time is misleading

// "User watched 90 seconds." Good or bad?
// 30-second video → incredible (3× rewatch)
// 180-second video → bad (watched only half)
 
// Raw watch time is confounded by video length.
// Also confounded by: time of day, user's historical behavior, device type...
// These are "bias features" — things that affect watch time
// but have NOTHING to do with whether this specific user liked this specific video.

The dual-tower decoder — every number shown

// Each decoder has TWO paths:
 
z_passive → LatentTower(z_passive) → residual prediction
bias_features → BaselineTower(bias) → baseline prediction
// (video length, stop_gradient!
// user avg WT,
// time of day)
 
final_logit = LatentTower(z_passive) + stop_gradient(BaselineTower(bias))
 
// stop_gradient = treat baseline output as a constant during backprop.
// Gradients flow ONLY through z_passive, not through bias_features.

Why stop_gradient is the key

// Without stop_gradient:
// Both z_passive AND bias_features compete to explain watch time.
// The encoder learns to put video-length info into z_passive.
// z_passive ends up encoding "how long was the video" not "how much did user value it"
 
// With stop_gradient:
// BaselineTower has already "explained" the predictable part (video length, etc.).
// The only gradient the encoder receives is for the RESIDUAL — the unexplained part.
// z_passive is forced to capture: "how much MORE or LESS did this user watch
// than we'd expect given the video length and their history?"

Concrete example — what z_passive actually captures

video: 120s, average user at 8 PM
BaselineTower prediction: 45s watch time
// "For a 120s video with this user profile at 8 PM, we'd normally expect 45s"
 
User A actually watched: 80s
// residual = 80 - 45 = +35s → z_passive = HIGH
// "This user valued this video 35s more than expected"
 
User B actually watched: 20s
// residual = 20 - 45 = -25s → z_passive = LOW
// "This user valued this video 25s less than expected"
 
// z_passive no longer cares that the video was 120s.
// It only captures the USER-SPECIFIC deviation from what was predictable.

The Final Scoring Formula and What It Achieved

Old formula vs new formula

// OLD (7+ hyperparameters, 13 separate heads):
Score = (1.1×SAT_WT + 0.05×Novel_WT + 0.45×WT - w×VLEN) × (pSat×pOffputting)^0.7
// Every term needs tuning. Adding a new signal = adding a new hyperparameter.
 
// NEW (1 hyperparameter):
GoodLift = sigmoid(z_valence) × z_passive
GoodLogWT = log(sigmoid(z_valence) × pWT + 1)
VLC = 0.005 × video_length
 
Score = GoodLift + GoodLogWT - VLC

Why GoodLift = sigmoid(z_valence) × z_passive makes intuitive sense

// Case 1: watched a lot AND liked it
z_passive = 3.0, z_valence = 2.0
GoodLift = sigmoid(2.0) × 3.0 = 0.88 × 3.0 = 2.64 ← high
 
// Case 2: watched a lot but DISLIKED it
z_passive = 3.0, z_valence = -2.0
GoodLift = sigmoid(-2.0) × 3.0 = 0.12 × 3.0 = 0.36 ← low despite watching!
 
// Case 3: didn't watch, neutral
z_passive = 0.5, z_valence = 0.0
GoodLift = sigmoid(0.0) × 0.5 = 0.5 × 0.5 = 0.25 ← medium
 
// sigmoid(z_valence) = "how much of the passive consumption was valued?"
// If z_valence is negative (dislike), sigmoid squashes the passive score.
// This prevents "rage watching" from looking like positive engagement.

// What they share: reparameterization trick, bottleneck, KL regularization
// What varies: HOW the latents are constrained
 
// Unsupervised VAE: latents emerge from reconstruction signal alone
// Supervised VAE: latents are routed to specific supervised decoders
// Disentangled VAE: regularization forces latents to be independent
// Conditional VAE: condition the decoder on external labels (class, text, etc.)
